# 适配器契约

状态：设计草案。

## 文本加载

`@loadlet/node` 提供 `textLoader()` 与 `readText(file, context)`。两者接受绝对 `file:` URL，先等待 `track`，再读取 UTF-8 文本。

| 输入情况               | 行为                                                   |
| ---------------------- | ------------------------------------------------------ |
| 正常文本               | 原样保留 BOM、换行和空白                               |
| 缺失、不可读或目标无效 | 加载失败，已登记目标保留相应恢复能力                   |
| 相对文件路径           | 调用方先通过 `new URL()` 或 `pathToFileURL()` 确定来源 |
| 文本引用附加文件       | 用户处理函数解析引用，并通过 `readText` 跟踪读取       |
| JSON、YAML 等格式      | 由用户选用解析器，决定格式与结构语义                   |

## 模块加载

`@loadlet/module` 的 `moduleLoader()` 接受入口 URL，在顶层求值完成后返回完整模块命名空间。成员类型为 `unknown`；选择 default、调用导出函数、解包导出的 Promise 及结构校验均由用户处理函数完成。

### 首个实现的验收目标

以下能力须由选型实验逐项确认，并形成有版本依据的支持矩阵。

| 主题       | 要求                                                           |
| ---------- | -------------------------------------------------------------- |
| 基础语法   | 本地 ESM JS、TS，静态 import、export from、字面量动态 import   |
| JSON 依赖  | 明确支持的导入语法，使用统一诊断与监听规则                     |
| 重新求值   | 每轮执行入口和支持范围内的本地运行时依赖，子模块改动可得到新值 |
| 失败恢复   | 语法错误及缺失静态相对依赖的恢复候选在失败前登记               |
| 解析元数据 | 登记影响解析的本地 package.json 等输入，入口选择变化触发重算   |
| workspace  | 覆盖 node_modules 外的本地源码，包括项目 root 之外的文件       |
| 源位置     | 支持的定位能力指向源文件；import.meta 各成员单独验收           |
| 并行会话   | 临时产物与求值轮次隔离，清理、取消互不干扰                     |

依赖跟踪还必须满足读取窗口的保护要求。执行器返回依赖列表后，适配器仍需证明读取、监听安装及失败恢复之间的交接完整；可采用读前登记或经验证的等价协议。仅重新执行入口而复用旧子模块缓存，不能满足重新求值要求。

### 支持范围

| 类别                                  | 处理原则                                                                             |
| ------------------------------------- | ------------------------------------------------------------------------------------ |
| 外部包                                | 显式记录外部化规则；普通 node_modules 包可沿用运行时缓存，包内改动不纳入自动重载保证 |
| 非字面量动态加载                      | 根据执行器实际能力声明发现、刷新和监听范围                                           |
| 隐式文件读取                          | 由用户显式登记，或移到处理函数使用跟踪读取                                           |
| 环境变量、网络与时间                  | 作为调用方管理的输入，模块加载器不自动监视                                           |
| CommonJS、require、后缀推断、目录导入 | 选型后分别确定加载、解析、缓存与监听语义                                             |
| 别名、自定义解析条件                  | 由明确的加载器或宿主适配能力提供                                                     |

执行器的选择须显式确定。失败后静默切换执行器可能改变语义，不属于支持策略；无法满足某项契约时，应调整适配器或缩小声明范围。

### 资源与清理

加载器在 Promise 完成前释放本轮临时产物等内部资源。

| 求值与清理结果       | 对外结果                     |
| -------------------- | ---------------------------- |
| 求值成功、清理成功   | 返回加载值                   |
| 求值成功、清理失败   | 以 `CLEANUP_FAILED` 拒绝本轮 |
| 求值失败、清理也失败 | 主要错误为首项，追加清理诊断 |

适配器可抛出合规的 `LoadletError`，核心保留其诊断顺序。用户模块在 Node 宿主进程执行，timer、连接等长期资源应由消费结果的业务层建立和释放。后续实验应记录重复求值的 ESM 缓存、内存趋势与长时间运行成本。

## 监听协议

`Watcher.connect(notify)` 为每次会话建立独立的 `WatchConnection`；`fileWatcher()` 提供本地文件实现入口，底层后端通过协议验收后确定。

| 操作或事件      | 必须满足的行为                                                       |
| --------------- | -------------------------------------------------------------------- |
| `connect`       | 返回本会话连接；未能返回时清理已分配的部分资源                       |
| `add(files)`    | 幂等登记精确文件；目标不存在时监听最近可用祖先，并随目录创建向下跟进 |
| add 完成        | 目标已可安全读取；安装期间的变化通过缓冲或校验补发覆盖               |
| `remove(files)` | 幂等移除本连接登记，保留其他会话及宿主的监听                         |
| `close()`       | 等待或取消此前操作；释放失败也必须停止本连接的通知入口               |
| `change`        | 内容变化、删除、重建、原子替换和符号链接重定向使对应目标失效         |
| `error`         | 监听完整性无法保证时报告原始原因，核心据此终止会话                   |

输入是无查询和片段的绝对 file URL 字符串，事件须映射回登记身份。符号链接同时覆盖访问路径和真实目标，避免丢失链接重定向。核心串行调用 `add/remove/close`，`notify` 可在任意等待期间到达。

### 共享宿主 watcher

宿主适配器须提供独立监听所有权或引用计数。若底层无法安全 unwatch，可移除本连接的事件路由，并明确系统监听保留至宿主关闭；核心逻辑依赖集合仍按成功结果更新。释放 Loadlet 会话不能关闭宿主 watcher 或移除其他使用者的监听。

共享实现同样需要兑现 add 就绪语义。宿主缺少 ready 信号时，须提供等价检查机制，并通过并发验收；调用 `add()` 本身不构成无遗漏的证据。

## 宿主集成

Loadlet 管理加载结果，宿主管理结果所处的应用生命周期。

| 责任                                                | 归属                     |
| --------------------------------------------------- | ------------------------ |
| 配置输入的依赖、重载、恢复和配置会话关闭            | Loadlet                  |
| Vite env、define、alias、虚拟模块、import.meta.glob | 明确声明能力的宿主适配层 |
| uni-pages prepare 幂等、参数一致性与实例占用        | uni-pages                |
| 页面扫描、产物提交、下游缓存与业务错误恢复          | 消费者                   |

prepare 与正式 Vite 环境使用独立、参数稳定的会话。交接顺序为：等待准备工作完成，关闭旧会话，以正式环境打开新会话，再由宿主采用结果。宿主同时定义交接期间输入变化、初始化失败、重启重叠与关闭通知缺失的处理路径。

集成验收见[消费者集成](scenarios.md#消费者集成)，调用示例见 [API](api.md)。
