## 加载与处理

| ID  | 场景                                     | 验收结果                                                 |
| --- | ---------------------------------------- | -------------------------------------------------------- |
| L01 | 一次文本加载与处理成功                   | 返回最终值、依赖及版本信息；释放本轮资源，不保留持续监听 |
| L02 | 首次读取或处理失败                       | 拒绝初始化；不返回快照或会话；清理失败追加在主要错误之后 |
| L03 | 用户解析器处理 YAML 文本                 | 发布用户返回的结构，解析器由用户提供                     |
| L04 | 处理函数跟踪读取附加文件并合并           | 入口与附加文件均登记；会话中修改任一输入触发重算         |
| L05 | 返回字符串、数组、函数、类实例或自定义值 | 保持结果类型，历史稳定性遵循值的所有权约定               |
| L06 | 组合解析、合并、校验，其中一步失败       | 后续处理停止；不发布局部结果；诊断标识处理阶段与尝试编号 |
| L07 | 普通文件 API 读取未登记文件              | 该文件不在自动跟踪保证内；显式登记后具备重载保证         |
| L08 | 自定义加载器从来源描述读取多个文件       | 所有输入由加载器登记，核心统一管理依赖集合与结果         |

## 依赖与恢复

| ID  | 场景                                     | 验收结果                                           |
| --- | ---------------------------------------- | -------------------------------------------------- |
| D01 | 下一次成功求值新增依赖 B                 | B 加入监听，后续修改 B 触发完整求值                |
| D02 | 下一次成功求值移除依赖 B                 | B 退出本会话集合，之后仅修改 B 不再触发重载        |
| D03 | 成功后入口或依赖出现语法错误，再修复     | 失败时保留当前值与成功版本，修复后继续发布         |
| D04 | 读取前已登记新目标 B，但 B 缺失          | 保留成功值；创建 B 即可恢复，无需再改入口          |
| D05 | 连续失败分别发现缺失目标 B、C            | 累计保留 B、C 与最后成功依赖；后续成功替换累计集合 |
| D06 | 已加载入口被删除后重建                   | 删除时保留旧值并诊断，重建后恢复                   |
| D07 | 自定义加载器对已登记的缺失入口返回默认值 | 默认值作为成功结果发布，创建入口后仍重载           |
| D08 | 加载与处理重复登记同一文件               | 只有一份逻辑依赖，不泄漏监听引用或重复发布         |
| D09 | 编辑器原子替换文件，或删除后同路径重建   | 保持路径恢复能力，后续结果反映新的完整输入         |
| D10 | 已登记目标的父目录也缺失，随后逐层创建   | 跟进祖先目录变化，目标创建后可恢复                 |

## 时序与监听

| ID  | 场景                                     | 验收结果                                                 |
| --- | ---------------------------------------- | -------------------------------------------------------- |
| O01 | 求值期间已登记输入连续变化               | 同时最多一轮加载与处理，事件合并补跑，过期结果不发布     |
| O02 | 新依赖 B 的监听尚未就绪时 B 变化         | 就绪握手或等价校验使过期轮补跑，覆盖读取窗口             |
| O03 | 初始化监听时入口变化                     | 等待有效首轮，捕获变化并完成交接                         |
| O04 | 重复事件与手动重载汇合                   | 请求可合并，成功版本按实际发布次数递增                   |
| O05 | 旧轮在失效或关闭后才成功                 | 禁止旧结果发布，不改写后续轮次或关闭状态                 |
| O06 | connect、add、remove 失败或 watcher 报错 | 报告 `WATCH_FAILED`，保留 current 并终止；恢复需重新打开 |
| O07 | 用户函数忽略取消且长期不返回             | 后续求值与关闭等待，迟到结果仍不发布                     |
| O08 | 两个会话同时加载同一来源                 | 版本、诊断、监听引用及关闭相互独立                       |
| O09 | 两次 reload 取代在途轮，下一轮成功       | 过期轮不结算请求，两个等待者可共享有效快照               |
| O10 | reload 等待期间有效轮失败或会话关闭      | 主要失败或 `SESSION_CLOSED` 拒绝等待者，排队请求均可结算 |

## 快照与生命周期

### 发布与订阅

| ID  | 场景                                   | 验收结果                                                                       |
| --- | -------------------------------------- | ------------------------------------------------------------------------------ |
| S01 | 成功打开后订阅                         | 同步取得 current，再有序接收后续事件，无注册遗漏窗口                           |
| S02 | 成功后更新失败，再恢复成功             | 失败不增加版本，恢复发布下一版本；attempt 可区分各轮                           |
| S03 | 两次成功结果在业务上相等               | 仍发布新版本，结果相等不成为隐式去重条件                                       |
| S04 | 一个订阅回调抛错                       | 取消失败订阅并报告 `SUBSCRIBER_FAILED`，其余订阅继续接收原事件，快照保持已发布 |
| S05 | 消费者异步重连或生成产物失败           | 消费者处理业务错误，Loadlet 成功版本保持不变                                   |
| S06 | 保存旧快照后产生新结果                 | 核心不修改旧快照，用户值遵循所有权约定                                         |
| S07 | 取消订阅后继续重载                     | 停止该订阅的新投递，其他订阅正常                                               |
| S11 | 回调内新增订阅或调用 close             | 新订阅同步回放一次，不重复参加当前广播；close 截断后续广播，包括监听故障通知   |
| S15 | JavaScript 调用者误传 async 回调并拒绝 | 核心消费拒绝但不等待；开放时按订阅失败处理，关闭后不再通知                     |

### 取消、清理与上下文

| ID  | 场景                                         | 验收结果                                                                            |
| --- | -------------------------------------------- | ----------------------------------------------------------------------------------- |
| S08 | 空闲或求值期间关闭，并重复调用               | 幂等等待在途工作与资源释放，停止新更新；完成后无通知                                |
| S09 | 关闭后读取 current，再 reload                | 成功值仍可读，reload 明确拒绝，会话保持终态                                         |
| S10 | 从准备环境切换到正式环境                     | 创建新会话与新 id，宿主管理 id 与环境的对应                                         |
| S12 | 初始化失败后清理也失败，或 close 清理失败    | 初始化保留主要错误并追加诊断；close 返回清理诊断并保持 closed，重复调用取得同一结果 |
| S13 | signal 在调用前或初始化期间中止              | 以 `ABORTED` 拒绝并清理，迟到结果不发布                                             |
| S14 | 已打开会话的 signal 中止，尚有 reload 等待者 | 自动关闭，等待者以 `ABORTED` 拒绝；close 可取得同一清理结果                         |
| S16 | 求值成功但适配器临时产物清理失败             | 本轮以 `CLEANUP_FAILED` 拒绝，保留最后成功快照                                      |

## 模块能力

每种语法分别记录加载、依赖收集、缓存刷新与监听能力，形成执行器的支持矩阵。

| ID  | 场景                                                      | 验收结果                                               |
| --- | --------------------------------------------------------- | ------------------------------------------------------ |
| M01 | 入口经本地依赖间接导入第三个文件                          | 收集受支持的传递依赖，仅修改第三个文件也得到新值       |
| M02 | 两次加载之间只修改子模块                                  | 受支持依赖重新求值，返回修改后的值                     |
| M03 | 静态导入缺失目标，随后补齐                                | 解释并保留解析候选，目标修复后恢复                     |
| M04 | 字面量动态导入、变量动态导入、CommonJS、类型导入、外部包  | 分别确定加载、收集、刷新和监听范围                     |
| M05 | 目录导入、后缀推断、workspace 链接、package.json 导出条件 | 解析规则明确；支持范围内的解析元数据变化触发重算       |
| M06 | 使用源位置、import.meta 或宿主专有变量                    | 源位置逐项验证，宿主语义有明确适配归属                 |
| M07 | 并行会话长期连续重载                                      | 临时产物独立，取消和清理互不影响，资源与内存趋势有记录 |

## 消费者集成

| ID  | 场景                                       | 通过条件                                                                                  |
| --- | ------------------------------------------ | ----------------------------------------------------------------------------------------- |
| I01 | 独立 Node 应用加载文本、解析并合并附加文件 | 经公开接口验证 D01–D07、O01–O03、S01–S09，应用负责来源、处理与结果采用                    |
| I02 | uni-pages 接入配置加载                     | 通用依赖、恢复集合、补跑队列及配置会话关闭由 Loadlet 承担，页面扫描与产物生命周期仍归插件 |
| I03 | 借用 Vite watcher，宿主仍有自身监听        | 释放只影响 Loadlet 的注册与订阅，其他会话和宿主正常运行                                   |
| I04 | prepare 完成后切换正式 Vite 环境           | 准备成功后交接会话并重新求值；准备失败保留原错；下游缓存由宿主管理                        |
| I05 | dev、单次 build、build watch 分别结束      | 在对应完整生命周期结束时关闭，build watch 的单轮结束保持会话                              |
| I06 | 初始化提前失败，或 restart 导致服务器重叠  | 关闭路径和实例所有权明确，能处理宿主关闭通知缺失                                          |

入口缺失的默认值由用户加载器定义；prepare 参数约束、Vite 环境注入与页面产物保留分别归属宿主和业务逻辑。
