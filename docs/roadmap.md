# 路线图

Loadlet 首版面向两类消费者：持续读取文本输入的 Node 应用，以及需要重新执行配置模块的开发工具。验收重点是让两者共用加载与更新机制，并减少自行维护的监听、恢复和调度状态。

## 首版范围

| 能力     | 目标                                               |
| -------- | -------------------------------------------------- |
| 加载     | 本地文本和 JS/TS 模块，适配器可独立选择            |
| 处理     | 用户组合普通函数，返回自定义类型的结果             |
| 依赖     | 加载与处理共同登记，覆盖新增、移除及缺失目标恢复   |
| 更新     | 整轮重新求值、串行调度、完整成功发布、失败保留快照 |
| 生命周期 | 一次加载、持续会话、订阅、手动重载、取消与关闭     |
| 集成     | 独立本地监听，以及通过协议借用宿主 watcher         |

格式解析、配置发现、合并、环境分层与 schema 校验由用户或专项适配器提供。远程来源、动态步骤编排和应用级 HMR 留待具体需求验证。

## 交付顺序

| 阶段     | 交付内容                               | 通过条件                                                             |
| -------- | -------------------------------------- | -------------------------------------------------------------------- |
| 接口设计 | 工作区、类型声明、设计与行为契约       | 类型和文档一致，加载、处理、会话与适配器责任明确                     |
| 文本会话 | 核心、文本加载、本地监听、独立消费者   | 修改、删除、重建和处理失败均可恢复；消费者无需维护依赖集合与加载队列 |
| 模块加载 | 执行器选型、JS/TS 适配器、支持矩阵     | 承诺范围内的依赖重新求值；缺失依赖可恢复；执行语义明确               |
| 宿主集成 | uni-pages 接入实验与行为差异记录       | 通用加载状态得到复用；宿主监听所有权、业务生成与生命周期职责清楚     |
| 发布准备 | 运行环境支持、资源与性能记录、发布文档 | 两类消费者通过验收；已知限制、包名、许可和版本策略明确               |

详细验收项目见 [场景矩阵](scenarios.md)，候选工具及证据见 [技术调研](research.md)。类型检查验证接口的组合关系，运行时行为由实现阶段的测试验证。

## 选型与验证

执行器和监听后端按同一组契约比较，重点检查读取与监听建立之间的变化、失败前的依赖记录、缓存刷新、并行会话隔离和资源清理。现代 ESM/Node 支持、诊断质量、依赖成本和长期维护成本共同决定选择。

实现阶段还需取得以下证据：

- 本地监听在目标平台上的原子替换、符号链接和缺失父目录恢复行为
- 模块加载的语法支持、外部包缓存、临时产物及长时间重载内存趋势
- uni-pages 在准备阶段、正式环境接管和关闭过程中的接入差异
- 业务消费者能够删除的通用状态，以及仍需承担的结果采用逻辑

每次扩大支持范围，都应同步更新接口说明、适配器契约与对应验收项。
